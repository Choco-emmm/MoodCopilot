# 记忆写入、聊天审批与文本隐私契约

## 写入边界

所有正式写入经过 `MemoryOrchestrator`，共同使用 `MemoryWritePolicy`。新属性键为用户可读中文，最多 64 个 Unicode 码点；正文规范空白后为 1–500 个码点。新类型仅有 `preference / relationship / habit / event / short_term_state / pattern`，工具 Schema 与校验共用 `MemorySafetyPolicy.MEMORY_TYPES`。旧英文键、历史类型只允许随原目标保留，不能用于创建新属性。

密码、密钥、私钥、Token、带凭证链接、内网/私有链接、手机号、邮箱及现有机密关键词命中均拒绝记忆写入，用户确认不能豁免。关键词命中只表示“触发受限资料规则”，不代表已判定真实商业机密。校验发生在版本、证据和索引变动前；超长模型结果丢弃，用户超长提交报错，不截断后写入。

中文凭证识别同时覆盖普通赋值、带引号的值、带引号的字段名，以及正文或代码块中嵌入的配置片段；普通“忘记密码”“学习 Token 原理”不因术语本身被阻止。模型出站副本与记忆写入复用该分类器，原始输入保持不变。

自动事实证据必须是用户正文、主动歌词或明确引用中的 1–160 个码点连续片段，规范 Unicode 和空白后匹配。助手回复、摘要和图片描述不能独立作证；脱敏占位符不能作证。匹配只验证引用存在，不机械证明语义正确。清洗和候选去重按用户、属性、类型、规范化值的完整指纹执行，同属性不同值保留为分支。

候选值规范化保留有语义的标点和符号，例如 `C++` 与 `C#`、`a+b` 与 `ab` 必须不同。新候选和拒绝值使用带 `v2:` 前缀的确定性哈希指纹，避免与旧格式碰撞；旧记录继续按原值读取匹配，不批量改写历史。新建属性拒绝混入其他文字、下划线、表情和不可见格式字符的内部键，历史目标仍可原样保留。聊天引用旧助手发言的兼容包装仅在证据副本中剥离，原始记录保持不变。

`assertionType=explicit` 描述用户原文的表达方式，不授予修改权限。自动来源可按既有规则建立新属性及升级候选；有生效正式记忆时，同值仅追加证据，不同值进入候选，不能自动替换、否定失效或升级覆盖。删除封印和拒绝指纹约束全部自动来源，包括候选拒绝后的重提取。已有正式记忆只能由对应的用户确认入口修改。同一聊天 run 已提出审批的属性不再自动抽取。

## 聊天工具和审批接口

Flash/Pro 共用一份工具注册表与状态图。`saveMemoryFunction` 只新增，属性存在返回 `TARGET_EXISTS`；`updateMemoryFunction` 接收 `memoryId / expectedValue / newValue / evidence`，必须审批，仅修改当前用户生效正式记忆的正文。键、类型和核心标记从服务端继承；目标不唯一时先询问。

网页 `POST /api/chat/conversations/{id}/runs` 声明 `approvalsInteractive=true`；小程序、旧入口和非交互通道缺省为 `false`。预览从数据库读旧值并保存到 run 事件表，不进入图检查点。读取失败、目标失效或旧值不符时 `canApprove=false`，只能暂不修改。

批准请求仍使用同一 run：

```json
{"decisions":[{"toolCallId":"call-a","approved":true,"editedValue":"用户编辑后的记忆正文"},{"toolCallId":"call-b","approved":false,"reason":"暂不修改"}]}
```

`editedValue` 可选且只用于修改工具，省略采用原建议；只允许替换新正文，不能改变目标、证据和工具。编辑校验在消费待批准状态之前完成；失败保留待确认状态与页面草稿。缺字段、错误类型、重复 ID、额外字段倒向整批默认拒绝，未点名项默认拒绝。网页每项独立保存草稿和选择；未提交草稿只存在当前页面，刷新恢复原建议。

工具结果中的 `userEdited=true` 和 `approvalSource=USER_APPROVAL_EDIT` 明确表示正文由用户在审批面板编辑。AI 应按返回的最终正文说明保存结果，不能把与原建议不同归因为系统写错，也不能擅自改回原建议。

写入结果以 `status / reasonCode / memoryId / executed / success` 表达：`APPLIED` 已保存，`UNCHANGED` 无需修改，`REJECTED` 未获准/不合规，`STALE` 旧版本已变化，`FAILED` 处理失败。`success` 仅兼容真实 `APPLIED/UNCHANGED` 结果。未知工具异常使用固定 `TOOL_EXECUTION_FAILED`，不回显异常正文，也不猜测未确认的副作用。

拒绝结果保留 `rejected=true`，包含 `executed=false`、固定说明和独立数据字段 `userReason`。`USER_DECLINED` 表示用户已拒绝，`NO_DECISION` 表示没有有效决定，`APPROVAL_UNAVAILABLE` 表示通道不能交互。AI 不能把用户拒绝说成系统禁止，不能把未执行说成保存成功；同一 run 中不得换调用 ID 重复申请同一已拒绝写入。

## 事务、恢复、删除与索引

候选批准和拒绝共用用户行锁。拒绝只允许 `PENDING → REJECTED` 条件更新，成功后才写拒绝指纹和发布后续事件；重复拒绝幂等，不能把已批准或已合并候选改为拒绝。相反的旧决定返回 HTTP 409，网页刷新记录并说明该项已经处理，不把冲突显示成成功。

正式记忆编辑生成新版本后，网页必须重新取得当前记录的 ID、时间和版本元数据，并清除旧详情缓存，不能仅在原 ID 上替换正文。保存失败保留草稿；保存已成功而刷新失败时明确区分结果，禁止使用旧 ID 继续编辑、删除或查详情，待刷新成功后恢复操作。记忆中心编辑和候选弹框使用固定行数文本框，长文本内部滚动。

Flyway `V1_63__add_memory_change_commands.sql` 创建修改命令回执表，唯一键为 `user_id + run_id + tool_call_id`。回执只保存目标 ID、值哈希、状态和结果 ID，不长期复制记忆正文。正式写入共享用户行锁，版本替换检查目标、有效状态和预期旧值；并发变化返回 `STALE`，不覆盖新版。

新版本、`previousMemoryId`、历史证据归属、用户操作证据和成功回执在同一事务提交。用户编辑结果记录为 `USER_ACTION`，不伪装成聊天原文。同调用同内容重试复用结果，换内容拒绝；拒绝修改同样持久化为终止状态。数据库提交后检查点未保存的恢复不会重复生成版本。

暂停审批不是结束：不发 `done`、不置成功、不落半截助手历史、不启动记忆抽取。批准后从同一 `runId` 检查点重建累加器续跑，决定消费一次。客户端按事件和当前 run 状态恢复，历史批准帧不能使已完成审批再次弹出。

索引在事务提交后增量同步，失败不把已保存结果改称失败。修改回执保留 `index_pending`，定时重试同步并在成功后清除；RAG 与查询工具读取正式记忆前重新核对数据库有效版本和用户归属，旧向量不得恢复已失效事实。删除源属性时回执清空键、目标/结果 ID 和内容哈希，只保留防重调用墓碑。合并先版本化保存目标，再清除其他源属性；目标历史保留，清源封印与回执清理同事务执行。

## 模型请求与日志

`ModelRequestSanitizer` 处理脱离原始记录的出站消息副本，覆盖主日记分析 Flash/Pro、聊天首次及后续循环中的文本历史、引用、工具 JSON 和必要推理字段。保留消息角色、工具调用 ID、JSON 结构、鉴权头、真实工具入参和图片地址。脱敏失败禁止发送原文；已保存日记不受影响。

本轮出站保护只识别文本凭证及受限链接，不新增默认 OCR，不宣称覆盖图片像素或所有商业机密。手机号、邮箱禁止记忆，但普通聊天的联系方式不在本次凭证脱敏范围内扩张。“忘记密码”“学习 Token 原理”等普通讨论不会仅因术语出现被当作凭证值。

相关诊断记录 ID、原因类型、长度、数量及安全来源位置，不记录正文、证据、拒绝理由或敏感异常内容。精确的 ResizeObserver 延迟通知消息单独计数并每分钟限频，其他全局异常仍报告。网页输入框采用原生 textarea 和隐藏镜像，最多六行，支持输入法组合期间 Enter 不发送；审批正文为固定行数编辑框。

## 验证与发布边界

默认 CI 不调用真实 AI，也不连接生产数据。后端执行 `mvn --batch-mode --no-transfer-progress clean verify`，网页执行 `npm run test:interactions` 与 `npm run build`，最后 `git diff --check`。真实 HTTP 出站副本测试使用本地假服务；事务测试使用 H2 的实际 MyBatis、Spring 事务和新迁移 DDL，覆盖回滚、并发、恢复、防重、删除及索引失败。真实 AI 与浏览器闭环使用独立本地测试数据，另行记录结果。

新增字段为兼容扩展，旧客户端不能获得额外批准能力，小程序保持非交互模式。本次不批量改名、重分类或删除历史数据；受限历史记忆和证据不进入新的上下文或索引。生产迁移、部署和历史清理需另行安排。
