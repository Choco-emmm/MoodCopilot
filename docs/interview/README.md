## 使用顺序

1. 先读演示脚本，使用虚构数据准备私密演示账号。
2. 对照代码路径，至少能解释 `conversationId`、`runId`、`contextId` 的区别，以及为什么刷新不是重发消息。
3. 简历使用对应岗位的一版，保留“需求主导、AI 辅助开发”的实际角色；不把代码中存在某机制写成自己已独立掌握。
4. 后端可用后，按演示脚本完成一次计时彩排和备用录屏，再将清单标为通过。当前没有录屏文件，不要将脚本当作已录制演示。

证据复核命令（仓库根目录）：

```powershell
node docs/interview/verify-evidence.mjs
```

该脚本读取本轮 Maven 报告与历史压缩采样，并只探测本机两个 HTTP 地址；不调用 AI。后续若重新跑测试，应同步更新运行起止时间记录，避免把不同轮次的报告混在一起。
