# P1 修正约定

- 用户通过周/月报生成接口启动任务前，统一检查 REPORT 月配额。系统定时预生成保留独立入口，不混作用户请求扣额。
- 每次用户提交日记分析使用独立操作键；MQ 重投和执行重试复用已有 taskId。输入版本包含正文、图片及其元数据、用户音乐信息和主动歌词，不把异步生成的音乐摘要纳入输入指纹。回到以前的输入也不会复用已经完成或取消的任务。
- 过期投递恢复使用扫描到的租约所有者，并要求租约已过期、任务仍处于投递阶段；正常发布失败仍只允许当前节点处理自己的投递。条件更新失败不推进关联日记状态。
- 小程序私人引用携带用户归属。旧的无归属引用不再恢复；退出、身份改变及最终认证失败时清理引用，每次读取/发送仍校验当前身份。静默刷新同一账号可保留引用。

这些修正不包含此前 P2 的报告跨周期缓存、旧分析覆盖新版、图谱删除竞争或 Persona 修正。发布状态以对应提交的 CI/部署记录为准；微信小程序构建产物需另行发布。

回归入口：后端 ReportQuotaControllerTest、DiaryTaskInputTest、DispatchRecoveryTest；小程序 privateQuote.test.ts、quoteAuthentication.test.ts。用隔离数据和 mock 边界验证，无真实 AI 或生产数据操作。微信构建通过不等于设备换号验收，仍需在开发者工具/真机验证。

实际结果：修改前后端 4 项目标断言失败，小程序 2 项引用断言失败；修改后目标回归全部通过。后端 `clean verify`：324 项，0 失败、0 错误，2 项显式 opt-in 用例跳过。小程序 `npm test`：22 项通过；`type-check`、`build:mp-weixin` 和根目录 `git diff --check` 均通过。未运行真实模型、生产任务或设备换号流程。

静默续期返回不同或缺失用户 ID 时拒绝重放旧请求及等待队列；同账号续期仍允许重试，新增真实请求边界测试覆盖这两种结果。
