# 2026-08-08

## CI/CD 自动化流程建立

为 MoodCopilot 项目建立了完整的 GitHub Actions CI/CD 流水线，替代原有手工部署模式。
适配工作室 7 人团队，develop + main 双分支，不用 PR 直接合并/变基模式。

### 分支模型
- `develop`：7 人日常推送代码，push 后 CI 自动跑（ci.yml 触发于 push develop）
- `main`：合并 develop 后 push，自动触发部署（deploy.yml 触发于 push main）

### 新增文件
- `.github/workflows/ci.yml` — PR/push 到非 main 分支触发：后端 Maven 测试、前端 vue-tsc 构建、小程序 type-check+build、Docker 构建验证、Trivy 安全扫描
- `.github/workflows/deploy.yml` — push 到 main 触发：构建 Docker 镜像 → 推送 GHCR → SSH 部署 → 健康检查(30次重试) → 失败自动回滚 → 旧镜像清理(保留10个)
- `.github/workflows/backup.yml` — 每天 UTC 19:00 (北京时间 03:00) 自动执行 backup.sh + 备份完整性校验
- `backend/moodcopilot/.dockerignore` — 减少 Docker 构建上下文
- `frontend/.dockerignore` — 同上
- `docs/cicd-setup.md` — CI/CD 配置指南（Secrets、GHCR、SSH 密钥、首次使用步骤）

### 修改文件
- `backend/moodcopilot/Dockerfile` — 改为多阶段构建（Maven build stage + JRE runtime stage），CI 可直接从源码构建完整镜像
- `docker-compose.yml` — backend 和 web 服务添加 `image: ghcr.io/...` 字段，支持从 GHCR 拉取预构建镜像（保留 build 字段供本地开发）
- `deploy.sh` — 重写为支持 `--pull`（CI/CD 拉取镜像模式）和 `--build`（本地构建模式），增加健康检查和自动回滚逻辑

### 待用户操作
1. 在 GitHub 仓库 Settings → Secrets 配置 DEPLOY_HOST/DEPLOY_USER/DEPLOY_SSH_KEY/DEPLOY_PORT/DEPLOY_PATH
2. 确保服务器可拉取 GHCR 镜像（Private 需配置 GHCR_TOKEN）
3. (可选) 创建 GitHub production environment 并设置 required reviewers
4. 首次 push 到 main 触发 deploy.yml 后，到 GitHub Packages 确认镜像可见性
